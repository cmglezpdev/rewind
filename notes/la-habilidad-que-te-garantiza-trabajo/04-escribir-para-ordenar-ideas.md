# 4. Escribir el problema, los requisitos y la solución

DaveOps propone empezar por la escritura para desarrollar la capacidad de explicar soluciones técnicas. Su ejemplo es diseñar un sistema de chat. [`6:06`](https://www.youtube.com/watch?v=V83FARBbaT8&t=366)

## Ejercicio

1. Escribe el problema que debes resolver, por ejemplo, diseñar un sistema de chat. [`6:06`](https://www.youtube.com/watch?v=V83FARBbaT8&t=366)
2. Anota qué necesitas averiguar antes de diseñarlo:
   - Cuántas personas se conectan al sistema. [`6:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=383)
   - Cuánto pesa cada mensaje. [`6:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=383)
   - Cuántos mensajes se envían al día. [`6:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=383)
   - Qué requisitos de disponibilidad existen. [`6:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=383)
3. Escribe la solución y explica el porqué de las decisiones. Menciona WebSocket como ejemplo de decisión que habría que justificar; el pasaje no desarrolla una arquitectura completa ni aporta valores para los requisitos. [`6:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=383)
4. Prueba a hacerlo a mano. El autor lo prefiere porque considera que obliga a estructurar lo pensado para que tenga sentido al releerlo. [`6:54`](https://www.youtube.com/watch?v=V83FARBbaT8&t=414)

El resultado buscado es ordenar cómo entiendes el problema y cómo explicas su solución. La escritura es la primera parte de una práctica que continúa con la grabación. [`8:23`](https://www.youtube.com/watch?v=V83FARBbaT8&t=503)
