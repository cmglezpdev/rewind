# Pretraining evaluation

## Perplexity

- Perplexity exponentiates the average held-out next-token loss. Using natural logs, \(\mathrm{PPL}=\exp[-\frac1L\sum_t\ln p_\theta(x_t\mid x_{<t})]\); with base-2 logs, use \(2^{\text{average loss}}\). Averaging normalizes for sequence length. [`19:16`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1156) [`19:29`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1169) [`19:48`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1188)
- Perfect next-token predictions give perplexity 1. Uniform predictions over a vocabulary of size \(V\) give perplexity \(V\). The intuition is an effective number of candidate tokens. [`20:05`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1205) [`20:26`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1226)
- Mathematical clarification of the lecture's "between 1 and vocabulary size" shorthand: \(V\) is the uniform-prediction baseline, not a universal upper bound. Assigning the true token probability below \(1/V\) can produce perplexity above \(V\). [`19:48`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1188) [`20:05`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1205)
- The plotted historical example falls from roughly 70 to below 10 between 2017 and 2023. The transcript does not identify the dataset, so this is a reported example rather than a reproducible benchmark result. [`20:43`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1243) [`20:50`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1250)
- Perplexity remains useful during model development, but tokenizer and evaluation-data differences make raw values unsuitable for simple comparisons across models. The hypothetical 10,000-token versus 100,000-token vocabularies are illustrations, not reported product specifications. ## Multiple-choice benchmarks

- HELM and the Hugging Face open leaderboard aggregate automatically scored NLP tasks. MMLU collects multiple-choice questions across subjects including medicine, physics, and astronomy. [`21:26`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1286) [`21:46`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1306) [`22:30`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1350)
- Two scoring approaches are to compare the likelihoods of full candidate answers, or prompt for an answer letter and compare only the probabilities of `A`, `B`, `C`, and `D`. Neither requires unrestricted text generation. [`22:52`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1372) [`23:35`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1415) [`24:25`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1465) [`24:32`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1472) [`24:45`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1485)
- Evaluation implementation matters: the lecture reports Llama-65B scoring 63.7% on HELM versus 48.8% under another evaluation setup. The second setup is not named in the transcript. [`26:17`](https://www.youtube.com/watch?v=9vM4p9NN0Ts&t=1577)
- Training-test contamination undermines benchmark validity when a model has already seen the test data. One detection idea compares the likelihood of test examples in their original order against shuffled order; an unexplained preference for the original order suggests memorization. It is evidence, not proof of contamination.
