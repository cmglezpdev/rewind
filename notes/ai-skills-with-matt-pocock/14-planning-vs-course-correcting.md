# Planning vs course-correcting

- Matt says Grill Me is not for every task. It is for work that is large and expensive to undo if the agent gets it wrong. [`1:12:56`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4376)
- Upfront alignment matters when bad early code would stay in the context window and shape later work. [`1:12:56`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4376)
- Tiny changes, such as a small bug fix or moving a button a few pixels, do not need a grilling session. [`1:13:26`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4406)
- Matt has a workflow where small feedback becomes a GitHub issue, an implement agent fixes it, a review agent checks it, and he aligns after seeing the result. [`1:13:52`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4432)
- The decision rule is: align afterward for small tasks, use Grill Me for substantial single-session work, and use Wayfinder for work spanning multiple sessions. [`1:14:39`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4479)
- Matt distinguishes this from old waterfall by using aggressive prototyping before settling the spec. [`1:15:25`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4525)
- Agents make prototyping cheaper, so teams can build several rough versions, choose one, and iterate before committing. [`1:15:48`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4548)
- The host argues that the real failure mode of waterfall was multi-year planning and implementation, not short planning before short implementation. [`1:16:10`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4570)
- Matt sees agent workflows as closer to agile because cheap labor makes change easier. [`1:17:43`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4663)
