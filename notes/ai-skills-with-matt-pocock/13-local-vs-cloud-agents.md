# Local vs cloud agents

- Matt is moving away from a purely local dev setup because collaborative agent work needs more than one person and one terminal. [`1:09:17`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4157)
- He wants agent sessions to live where teams already communicate, such as Slack, Discord, Teams, or Linear. [`1:09:46`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4186)
- He works with remote agents from Discord, including while traveling, to build course material and fix student-reported bugs. [`1:10:11`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4211)
- Remote environments can stay on, run schedules, and host routines like a morning standup with an agent. [`1:10:36`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4236)
- Matt's local machine is mostly used to debug problems with the remote bot. [`1:10:58`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4258)
- Cloud environments can make complex dev setups easier by provisioning resources on demand. [`1:10:58`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4258)
- The host notes that companies with platform teams have moved local dev setups into cloud machines accessible from Slack or the web. [`1:11:32`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4292)
- The host says those companies see high voluntary cloud-agent use, while frontend work may remain an exception because it needs fast visual feedback. [`1:11:32`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4292)
- Matt argues that tunneled dev servers may make remote frontend workflows feel close to local workflows. [`1:11:57`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=4317)
