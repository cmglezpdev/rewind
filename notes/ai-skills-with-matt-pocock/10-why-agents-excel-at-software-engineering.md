# Why agents excel at software engineering

- The host contrasts software with other engineering fields: software behaves more deterministically than physical materials, while LLMs add variance back into the process. [`47:52`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=2872)
- Matt says agents fit software engineering because the inputs and outputs are mostly text. [`48:57`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=2937)
- Inputs include code, docs, and instructions; outputs include code, tests, type-checking results, and linting results. [`49:24`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=2964)
- Agents struggle more with non-text feedback, such as subtle UI animation or interaction problems. [`49:24`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=2964)
- Matt's practical rule is to make more work agent-friendly by turning signals, tools, and day-to-day interactions into text the agent can use. [`50:08`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=3008)
- He is trying to connect the services he uses to agents so those services become available inside agent workflows. [`50:37`](https://www.youtube.com/watch?v=4DhcSPkEbwI&t=3037)
