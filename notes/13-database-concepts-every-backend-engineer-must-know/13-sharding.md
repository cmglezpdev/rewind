# 13 — Sharding

- When the data **doesn't fit in one database**, you shard: **split the data across multiple databases** [`11:45`](https://www.youtube.com/watch?v=pEzrn6PIxRo&t=705).
- The challenge is on reads: **which shard holds the data you want?** [`11:45`](https://www.youtube.com/watch?v=pEzrn6PIxRo&t=705)
- Routing is typically solved with a **sharding key**, or a router using a **hashing technique** [`11:45`](https://www.youtube.com/watch?v=pEzrn6PIxRo&t=705).
- Warning: introducing sharding doesn't eliminate problems — it introduces new ones to deal with. **It's always a trade-off**, and this trade-off reasoning comes up a lot in system design interviews [`12:17`](https://www.youtube.com/watch?v=pEzrn6PIxRo&t=737).
