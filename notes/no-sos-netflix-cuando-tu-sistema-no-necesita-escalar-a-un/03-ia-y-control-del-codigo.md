# Usar IA sin perder control del sistema

La IA reduce el costo de producir código, pero desplaza el trabajo hacia entender, validar, integrar y operar lo que se produce.

- El cuello de botella ya no es necesariamente escribir código. Siguen pesando las pruebas, CI/CD, seguridad, escalabilidad y comprensión de la aplicación. [`12:49`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=769) [`13:18`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=798)
- **Asigna ownership.** Los equipos pueden fomentar herramientas de IA, pero una persona debe responder por el resultado y comprender qué hace el sistema. [`13:18`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=798)
- Generar módulos rápido no basta si nadie entiende su función o implementación. Construir rápido puede ayudar a escalar, siempre que el equipo pueda mantener lo construido. [`13:47`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=827)
- **Revisa el tamaño y la calidad del cambio.** Un pull request de 10.000 o 20.000 líneas no es razonable para revisar. Se pueden usar agentes para verificar reglas y dividir los cambios, pero una persona debe saber qué se está incorporando. [`15:14`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=914)
- No dejes que el sistema se convierta en una caja negra de decisiones y dependencias que el equipo no puede explicar. [`15:43`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=943)
- La rapidez no garantiza corrección. Usa IA para acelerar el trabajo, con pruebas, normas de seguridad y revisión humana. [`14:15`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=855) [`14:43`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=883)
