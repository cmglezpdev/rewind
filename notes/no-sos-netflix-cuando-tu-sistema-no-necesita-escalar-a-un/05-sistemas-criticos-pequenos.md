# Sistemas pequeños con alta criticidad

Un sistema puede manejar datos médicos o personales, dinero, procesos públicos sujetos a fechas o requisitos legales, y por eso tener consecuencias graves ante un error aunque lo usen pocas personas. [`19:08`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1148)

- **El margen de error es pequeño.** La charla se centra en sistemas de baja escala y alta criticidad, donde la prioridad es hacer bien el trabajo para pocos usuarios. [`19:41`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1181)
- **Controla los despliegues y define reglas claras** para frontend, backend y nube. Trata la infraestructura como código para que los cambios sean previsibles. [`20:08`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1208) [`20:22`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1222)
- **Prepárate para fallos y amenazas.** Define un modelo de amenazas. Cuando las políticas de datos lo permitan, usa modelos de lenguaje y agentes para revisar el código y buscar vulnerabilidades. El ponente menciona como experiencia haber perdido tres backups en tres lugares distintos el mismo día, una razón práctica para planear fallos múltiples. [`20:22`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1222) [`20:53`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1253)
- **Elige arquitectura por necesidad.** Para pocos componentes pueden bastar funciones o un monolito modular. Microservicios también pueden servir a equipos de cinco o diez personas, si existe una razón y se gestionan con coherencia. Evita distribuir solo un par de funciones. [`21:32`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1292) [`22:07`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1327)
- **Mantén el sistema simple y serio.** La simplicidad no equivale a fragilidad; usa arquitecturas conocidas y confiables en vez de reinventar componentes sin necesidad. [`22:27`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1347)
- Revisa confiabilidad, seguridad, recuperación desde cero, mantenibilidad, posibilidad de reemplazar componentes, auditoría y trazabilidad. El ponente menciona recuperar una instancia completa de AWS como caso de uso para pensar en imágenes de servicios y backups. [`23:07`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1387) [`23:38`](https://www.youtube.com/watch?v=nGeiH6GSIuU&t=1418)
