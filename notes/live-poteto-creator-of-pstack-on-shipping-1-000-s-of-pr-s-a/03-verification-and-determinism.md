# 3. Verification loops and deterministic tools

- Verification gives an agent "hands and eyes": it can run the application, interact with it as a user, debug it, and inspect traces or snapshots. Without access to the result, it cannot reliably iterate on its work. [`16:03`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=963) [`17:27`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1047)
- In an agent loop, verification is the part that lets the agent compare its result with a target and try again. Poteto used this for performance work and describes "hill climbing" as repeatedly improving a result against a rubric or score. [`17:55`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1075) [`18:33`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1113)
- His verification skill includes a custom CLI that wraps deterministic actions, including Playwright and Chrome DevTools Protocol calls. This prevents every agent from rebuilding its own verification scripts, which had wasted context, time, and effort. [`19:05`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1145) [`22:01`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1321) [`23:02`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1382)
- Poteto separates work that requires judgment from mechanical work. Scripts and CLIs should handle repeatable transformations or measurements; agents should focus on tasks that need interpretation and decisions. He applies the same idea to migrations, using codemods and AST transformations for mechanical changes. [`20:49`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1249) [`21:15`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1275) [`23:26`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1406) [`24:21`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1461)
- A skill can then stay small: it explains when and how to use the tools, while code provides consistent execution. [`21:43`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1303) [`22:27`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1347)
