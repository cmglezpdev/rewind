# 4. Shape the codebase to make good changes easier

- The new engineering work includes improving the environment in which agents operate. Without trust-building tools and processes, engineers can get trapped micromanaging agents and have little time to improve their setup. [`26:14`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1574) [`26:29`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1589)
- Poteto's internal Dune framework for Electron apps uses strict lint rules and conventional structure. Each feature has a dedicated directory, so agents have a clear place to put code and fewer opportunities to invent inconsistent patterns. [`30:01`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1801) [`30:30`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1830)
- This structure followed a concrete failure: early Grokbot versions accumulated eight "god files," each at least 10,000 lines long. Splitting features into directories made the code easier to navigate and constrain. [`31:01`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1861) [`31:32`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1892)
- When agents repeatedly make the same mistake, inspect the environment. Convert recurring errors into lint rules, types, conventions, or other guardrails so the codebase makes the bad path difficult or impossible. [`31:32`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1892) [`31:57`](https://www.youtube.com/watch?v=MN9dGgmLyso&t=1917)
- Poteto compares constraints in code to TypeScript narrowing: both reduce the set of possible states and clarify what the code can be. The result is less decision-making for both the human and the agent.
